# Эмулятор Командной Строки (Shell Emulator)

Эмулятор командной оболочки UNIX-подобной ОС, написанный на Python
с использованием `customtkinter`.

## Этап 1 — REPL-прототип

На данном этапе реализован минимальный интерактивный прототип оболочки
с командами-заглушками.

### Возможности

- Графический интерфейс на `customtkinter`
- Заголовок окна формируется из реальных данных ОС: `Shell Emulator - [user@host]`
- Парсер ввода: разделяет строку на команду и аргументы по пробелам
- Команды-заглушки:
  - `ls [аргументы]` — выводит имя команды и полученные аргументы
  - `cd [аргументы]` — выводит имя команды и полученные аргументы
  - `exit` — закрывает приложение
- Сообщение об ошибке в стиле UNIX для неизвестных команд
- Интерфейс на английском языке

## Этап 2 — Конфигурация

На данном этапе эмулятор стал настраиваемым: добавлены параметры
командной строки, отладочный вывод конфигурации и поддержка стартового
скрипта с командами.

### Возможности

- Параметры командной строки:
  - `--vfs <путь>` — путь к физическому расположению виртуальной
    файловой системы (по умолчанию `./vfs`)
  - `--script <путь>` — путь к стартовому скрипту с командами
    эмулятора (по умолчанию не задан)
- Отладочный вывод всех заданных параметров при запуске эмулятора
  (в stdout терминала)
- Стартовый скрипт:
  - выполняется построчно;
  - **останавливается при первой ошибке** (неизвестная команда);
  - в окне эмулятора отображается и ввод, и вывод — имитация
    диалога с пользователем.
- Скрипты реальной ОС в папке `examples/`, запускающие эмулятор
  с разными наборами параметров.

### Параметры командной строки

| Параметр   | Описание                                  | По умолчанию |
|------------|-------------------------------------------|--------------|
| `--vfs`    | Путь к физическому расположению VFS       | `./vfs`      |
| `--script` | Путь к стартовому скрипту                 | не задан     |

### Отладочный вывод

При запуске эмулятор печатает в stdout все итоговые параметры:

```
=== Конфигурация эмулятора оболочки ===
Путь к VFS     : /home/mark/practikaKY/vfs
VFS существует : True
Путь к скрипту : /home/mark/practikaKY/scripts/demo.txt
Файл скрипта   : True
======================================
```

### Стартовый скрипт

Скрипт выполняется построчно и **останавливается при первой ошибке**.
В окне эмулятора отображается и ввод, и вывод, имитируя диалог.

Пример `scripts/demo.txt` (без ошибок):

```
ls
ls -la /home
cd /tmp
cd ..
ls final
exit
```

Пример `scripts/errors.txt` (выполнение прервётся на неизвестной команде):

```
ls
cd /var
unknown_command --flag
ls never_reached
```

### Скрипты реальной ОС

В папке `examples/` лежат примеры запуска эмулятора с разными параметрами:

| Скрипт                     | Что делает                                |
|----------------------------|-------------------------------------------|
| `run_default.sh`           | Запуск с настройками по умолчанию         |
| `run_with_vfs.sh`          | Запуск с явно указанным путём к VFS       |
| `run_with_script.sh`       | Запуск с VFS и стартовым скриптом         |

Запуск:

```bash
./examples/run_default.sh
./examples/run_with_vfs.sh
./examples/run_with_script.sh
```

## Этап 3 — Виртуальная файловая система (VFS)

На данном этапе подключена настоящая VFS: все операции выполняются
**в памяти**, исходный CSV-файл не модифицируется (кроме служебной
команды сохранения).

### Возможности

- VFS в памяти, построенная по CSV-файлу
- Формат CSV с поддержкой вложенности через полный путь
- Двоичные данные через `base64:` — префикс в колонке `content`
- Обработка ошибок загрузки: файл не найден, битый формат, неизвестный тип
- Команда `vfs-save <путь>` — сохранение текущего состояния VFS
  в исходном CSV-формате
- Реальные команды `ls` и `cd`, работающие поверх VFS
- Несколько примеров VFS: минимальный, с несколькими файлами,
  с ≥3 уровнями вложенности

### Формат CSV

```
type,path,content
dir,/home,
file,/home/mark/notes.txt,Hello world
file,/home/mark/photo.png,base64:iVBORw0KGgo=
```

- `type` — `dir` или `file`;
- `path` — абсолютный путь внутри VFS;
- `content` — текст или `base64:<данные>` для двоичных файлов;
- вложенность задаётся через полный путь: строка
  `file,/home/mark/notes.txt,...` автоматически создаёт папки
  `/home` и `/home/mark`.

### Команды

| Команда             | Описание                                    |
|---------------------|---------------------------------------------|
| `ls [путь]`         | Список содержимого папки                    |
| `cd <путь>`         | Смена текущего каталога                     |
| `vfs-save <путь>`   | Сохранить состояние VFS в CSV-файл          |
| `exit`              | Завершить работу                            |

### Примеры VFS

| Файл                    | Описание                                     |
|-------------------------|----------------------------------------------|
| `vfs/minimal.csv`       | Минимальный набор (папка и один файл)        |
| `vfs/files.csv`         | Несколько файлов в разных папках             |
| `vfs/nested.csv`        | ≥3 уровней вложенности                       |

### Обработка ошибок загрузки

При запуске с несуществующим CSV или битым форматом эмулятор выводит
сообщение об ошибке в терминал и не открывает окно:

```
=== Конфигурация эмулятора оболочки ===
CSV VFS        : /home/mark/practikaKY/vfs/nonexistent.csv
VFS существует : False
Путь к скрипту : (не задан)
Файл скрипта   : False
======================================
Ошибка загрузки VFS: Файл VFS не найден: /home/mark/practikaKY/vfs/nonexistent.csv
```

### Скрипты реальной ОС для VFS

| Скрипт                          | Что делает                                    |
|---------------------------------|-----------------------------------------------|
| `run_minimal_vfs.sh`            | Запуск с `vfs/minimal.csv`                    |
| `run_files_vfs.sh`              | Запуск с `vfs/files.csv`                      |
| `run_nested_vfs.sh`             | Запуск с `vfs/nested.csv` и стартовым скриптом|

Запуск:

```bash
./examples/run_minimal_vfs.sh
./examples/run_files_vfs.sh
./examples/run_nested_vfs.sh
```

### Стартовый скрипт `scripts/full_test.txt`

Проверяет все команды всех этапов, включая работу с VFS и обработку
ошибок (в конце скрипта — заведомо ошибочные команды):

```
# Проверка всех команд эмулятора и работы с VFS
ls
cd /home
ls
cd mark
ls
cd projects
ls
cd emulator
ls
cd /
ls
vfs-save /tmp/vfs_saved.csv
cd /nonexistent
ls /nonexistent
unknown_command
exit
```

## Требования

- Python 3.10+
- [uv](https://docs.astral.sh/uv/) — менеджер зависимостей и окружений
- Linux, macOS или Windows (разработка велась на Pop!_OS)

### Установка uv (если ещё не установлен)

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

## Установка и запуск

### Через `run.sh`

```bash
./run.sh
```

Скрипт сам выполнит `uv sync` и запустит приложение.

Можно передать параметры:

```bash
./run.sh --vfs ./vfs/nested.csv --script ./scripts/full_test.txt
```

### Через `make`

```bash
make install
make run
```

Дополнительные цели:

```bash
make demo       # запуск со скриптом scripts/demo.txt
make errors     # запуск со скриптом scripts/errors.txt (с ошибкой)
make minimal    # запуск с vfs/minimal.csv
make files      # запуск с vfs/files.csv
make nested     # запуск с vfs/nested.csv
make full-test  # запуск с vfs/nested.csv и scripts/full_test.txt
```

### Вручную через uv

```bash
uv sync
uv run python -m src.main --vfs ./vfs/nested.csv --script ./scripts/full_test.txt
```

## Использование

Введите команду в поле ввода и нажмите **Enter**.

```
user@host:/$ ls
home
tmp

user@host:/$ cd /home/mark
user@host:/home/mark$ ls
notes.txt
todo.txt

user@host:/home/mark$ vfs-save /tmp/vfs_saved.csv
VFS сохранена в /tmp/vfs_saved.csv

user@host:/home/mark$ cd /nonexistent
Нет такого каталога: /nonexistent

user@host:/home/mark$ unknown
shell: command not found: unknown

user@host:/home/mark$ exit
exit: shutting down...
```

[Conventional Commits](https://www.conventionalcommits.org/).

Примеры сообщений:

```

feat(script): реализовать выполнение стартового скрипта с остановкой при ошибке
```
